# Task: Structured audit result rendering

## Description

Replace the raw `JSON.stringify` result display with structured, human-readable renderers for each audit module. Each module gets a dedicated render function that presents results as tables with status badges, making it immediately clear what leaked, which protocols were detected, and whether the kill switch held.

## Acceptance Criteria

- [ ] **Leak Detection** renders as a 3-row table (DNS / WebRTC / IPv6) with PASS/FAIL/WARNING badges per check
- [ ] Failed leak checks expand to show leaked servers/IPs (e.g., "Leaked to: 8.8.8.8, 1.1.1.1")
- [ ] **Traffic Fingerprinting** renders a protocol breakdown table (Protocol | Packets | Percentage) with horizontal bars proportional to packet count
- [ ] VPN ratio displayed with color coding: green (<3%), yellow (3-10%), red (>10%)
- [ ] Fingerprint verdict text displayed from the `reason` field
- [ ] **Kill Switch** renders summary: Duration, Total Packets, Tunnel Packets, Leaked Packets
- [ ] If leaked > 0: shows per-interface breakdown table and time-to-block value
- [ ] If leaked = 0: shows green "Kill switch held — no leaks detected" message
- [ ] **Full Audit** card dispatches to individual module renderers and updates individual cards
- [ ] Status badges use existing CSS vars: `--color-pass` (#4caf50), `--color-fail` (#f44336), `--color-warning` (#ff9800)
- [ ] Result tables use compact styling consistent with existing route/interface lists
- [ ] Raw JSON is no longer shown to users
- [ ] All rendering functions are module-internal to `app.js` (no new files)

## Technical Details

### Files Modified
- `frontend/js/app.js` — Replace `renderSingleResult()` with dispatcher that calls module-specific renderers based on result data shape. Add three render functions:
  - `renderLeakResult(el, data)` — inspects `data.details` for dns/webrtc/ipv6 sub-objects
  - `renderFingerprintResult(el, data)` — inspects `data.details` for protocol breakdown, VPN ratio, reason
  - `renderKillswitchResult(el, data)` — inspects `data.details` for leaked_packets, duration, per-interface data
  - Keep `renderSingleResult()` as fallback for unknown result shapes
- `frontend/css/style.css` — Add styles: `.result-table`, `.status-badge`, `.status-badge.pass/fail/warning`, `.protocol-bar`, `.protocol-bar-fill`, `.leak-detail`, `.ks-summary`

### Result dispatch logic
```javascript
function renderSingleResult(el, data, auditType) {
  if (auditType === "leaks") return renderLeakResult(el, data);
  if (auditType === "fingerprint") return renderFingerprintResult(el, data);
  if (auditType === "killswitch") return renderKillswitchResult(el, data);
  // fallback: existing status + details display
}
```

Update `runAudit()` and `fetchStoredResults()` to pass `target` as `auditType` to the renderer.

### Data shapes (from existing core modules)
**Leak Detection** (`data.details`):
```json
{"dns": {"leaked": false, "servers": []}, "webrtc": {"leaked": true, "ips": ["203.0.113.5"]}, "ipv6": {"leaked": false, "addresses": []}}
```

**Fingerprinting** (`data.details`):
```json
{"total_packets": 150, "protocols": {"wireguard": 120, "openvpn": 0, "https": 25, "other": 5}, "vpn_ratio": 0.033, "reason": "Low non-VPN traffic detected"}
```

**Kill Switch** (`data.details`):
```json
{"duration": 30, "total_packets": 500, "tunnel_packets": 498, "leaked_packets": 2, "per_interface": {"eth0": 2}, "time_to_block": 1.5}
```
