# Task: Per-interface bandwidth monitoring

## Description

Replace aggregate-only bandwidth measurement with per-interface bandwidth tracking to detect split-tunneling leaks where traffic flows through the physical adapter instead of the VPN tunnel. Backend computes per-NIC deltas, frontend displays bandwidth per interface with warning highlights on non-tunnel interfaces carrying significant traffic.

## Acceptance Criteria

- [ ] `estimate_bandwidth()` uses `psutil.net_io_counters(pernic=True)` instead of aggregate
- [ ] Returns both `bandwidth_mbps` (aggregate sum) and `bandwidth_per_interface` dict (per-NIC Mbps values)
- [ ] Interfaces with 0.0 Mbps are filtered out of `bandwidth_per_interface` to reduce noise
- [ ] `snapshot()` includes `bandwidth_per_interface` in its output dict
- [ ] WebSocket monitor streams `bandwidth_per_interface` alongside existing `bandwidth_mbps`
- [ ] `bandwidth_mbps` field remains a number (backward-compatible)
- [ ] Frontend interface list shows bandwidth indicator per interface item
- [ ] Non-tunnel interfaces with >0.1 Mbps traffic get a warning highlight (CSS class)
- [ ] Tunnel interface bandwidth shown in green (expected traffic)
- [ ] Aggregate bandwidth gauge continues working (uses `bandwidth_mbps`)
- [ ] Existing tests updated and passing

## Technical Details

### Files Modified
- `backend/core/monitor.py` — Update `estimate_bandwidth()` to use `pernic=True`, compute per-NIC byte deltas, return `{"bandwidth_mbps": float, "bandwidth_per_interface": dict}`. Update `snapshot()` to unpack both values.
- `frontend/js/app.js` — Update `updateInterfaces()` to accept bandwidth data and append Mbps indicator to each interface item. Add warning class for non-tunnel interfaces >0.1 Mbps. Use `interfaces.py` tunnel classification logic (match by name prefix: tun, wg, proton, nordlynx, etc.).
- `frontend/css/style.css` — Add `.iface-bandwidth` indicator style, `.iface-bandwidth-warning` highlight style, `.iface-bandwidth-ok` green style
- `tests/test_monitor.py` — Update `TestBandwidth` to mock `pernic=True` return value (dict of named tuples), verify both aggregate and per-interface output. Update `TestSnapshot` to verify `bandwidth_per_interface` in snapshot.

### Backend return format
```python
def estimate_bandwidth(self, sample_interval=0.5):
    # Returns tuple: (aggregate_mbps, per_interface_dict)
    return bandwidth_mbps, bandwidth_per_interface
```

### WebSocket data shape
```json
{
  "bandwidth_mbps": 12.5,
  "bandwidth_per_interface": {
    "eth0": 11.2,
    "tun0": 1.3
  }

```

### Frontend tunnel detection
Reuse the same prefix patterns from `backend/core/interfaces.py` on the frontend side:
- Tunnel prefixes: `tun`, `wg`, `proton`, `nordlynx`, `mullvad`, `utun`, `ppp`
- Simple string match on interface name
