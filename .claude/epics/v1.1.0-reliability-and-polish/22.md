# Task: External IP fallback chain + singleton cache fix

## Description

Add multi-API fallback to `ExternalIPChecker` so external IP lookups survive when ip-api.com is unavailable. Fix the cache bypass bug in `routes.py` where each `GET /api/external-ip` request instantiates a new `ExternalIPChecker`, defeating the 30s TTL cache. Add a `source` field to responses indicating which API provided the result.

## Acceptance Criteria

- [ ] `ExternalIPChecker.lookup()` tries fallback APIs in order: ip-api.com -> ipinfo.io -> ifconfig.me
- [ ] On primary API failure (network error, timeout, non-200, JSON decode), the next source is tried automatically
- [ ] All API responses are normalized to common schema: `{ip, country, city, isp, org, vpn_masked, source, status, timestamp}`
- [ ] `source` field indicates which API provided the result (e.g., `"ip-api.com"`, `"ipinfo.io"`, `"ifconfig.me"`)
- [ ] When all APIs fail but a cached result exists, return cached result with `status: "cached"` instead of `status: "error"`
- [ ] Only return `status: "error"` when all APIs fail AND no cached result exists
- [ ] Module-level `ExternalIPChecker()` singleton in `routes.py` replaces per-request instantiation
- [ ] `GET /api/external-ip` uses the shared singleton (cache works across requests)
- [ ] `ConnectionMonitor` in `websocket.py` continues using its own instance (no regression)
- [ ] All new fallback logic covered by unit tests with mocked HTTP calls
- [ ] Existing tests continue to pass

## Technical Details

### Files Modified
- `backend/core/external_ip.py` — Add `_API_SOURCES` list with URL + response normalizer per API, update `lookup()` to iterate sources on failure, add `source` field to result dict
- `backend/api/routes.py` — Replace `ExternalIPChecker()` instantiation in `external_ip()` handler with module-level singleton `_ip_checker = ExternalIPChecker()`
- `tests/test_external_ip.py` — Add fallback tests (primary fails, secondary succeeds), all-fail-with-cache test, all-fail-no-cache test, source field assertions
- `tests/test_api.py` — Update `test_external_ip_*` tests to mock the module-level singleton instead of class constructor

### API Response Schema (unchanged fields + new `source`)
```json
{
  "ip": "185.159.157.1",
  "country": "Switzerland",
  "city": "Zurich",
  "isp": "Proton AG",
  "org": "Proton AG",
  "vpn_masked": true,
  "source": "ip-api.com",
  "status": "ok",
  "timestamp": "2026-03-08T00:00:00Z"
}
```

### Fallback API normalization
- **ip-api.com**: `query` -> `ip`, fields directly mapped
- **ipinfo.io**: `ip` -> `ip`, `org` may include AS number prefix (strip it), `city`/`country` direct
- **ifconfig.me**: `ip_addr` -> `ip`, limited fields (no ISP/org), set missing fields to `null`
